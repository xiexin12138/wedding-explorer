# 景点金币奖励配置功能

## 更新内容

为景点表单添加了"奖励金币数"配置项，管理员在创建景点时可以自定义打卡奖励的金币数量。

## 功能特性

### 1. 可配置金币奖励

- **默认值**: 10 金币
- **可配置范围**: 1-1000 金币
- **应用场景**: 可根据景点的重要性、难度、距离等因素设置不同的奖励

### 2. UI 优化

在添加景点表单中，将"解锁距离"和"奖励金币数"并排显示：

```
┌─────────────────────┬─────────────────────┐
│  解锁距离 (米)      │  奖励金币数         │
│  [   100   ]        │  [    10   ]        │
│  用户在此范围内可打卡│  打卡后获得的金币   │
└─────────────────────┴─────────────────────┘
```

### 3. 表单验证

- **最小值**: 1 金币
- **最大值**: 1000 金币
- **默认值**: 如果输入无效，自动恢复为 10 金币

## 使用方法

### 创建新景点时设置奖励

1. 点击地图上的"添加新景点"按钮
2. 填写景点基本信息（名称、描述、类型等）
3. 在"奖励金币数"字段输入想要设置的金币数量
   - 留空将使用默认值 10 金币
   - 可设置 1-1000 之间的任意整数
4. 完成其他信息填写后提交

### 金币奖励建议

根据景点特点设置合适的奖励：

| 景点类型 | 建议奖励 | 说明 |
|---------|---------|------|
| 必游景点 | 20-50 金币 | 重要的、核心的景点 |
| 一般景点 | 10-20 金币 | 常规的、易到达的景点 |
| 隐藏景点 | 30-100 金币 | 难以发现、需要特别探索的景点 |
| 美食点位 | 15-30 金币 | 特色美食、餐厅 |
| 购物场所 | 10-25 金币 | 商场、特色店铺 |

## 代码变更

### 修改的文件

1. **components/AttractionForm.tsx**
   - 添加 `rewardCoins` 状态，默认值为 10
   - 添加金币奖励输入框 UI
   - 表单提交时包含 `rewardCoins` 字段

### 数据流

```
用户输入 → AttractionForm 
         → POST /api/attractions 
         → attractions.repository.ts
         → Prisma → Database (attractions 表)
```

## 效果展示

### 创建景点时

```typescript
{
  name: "深圳万象城",
  description: "高端购物中心",
  type: "SHOPPING",
  unlockDistance: 100,
  rewardCoins: 20,  // 可自定义
  // ... 其他字段
}
```

### 用户打卡时

```
1. 用户到达景点 → 点击"立即打卡"
2. 系统验证距离和状态
3. 打卡成功 → 获得 20 金币奖励 ✨
4. 显示: "恭喜你获得 20 金币奖励!"
```

## 向后兼容性

- ✅ 已有景点的 `rewardCoins` 默认为 10（数据库默认值）
- ✅ 不填写时自动使用 10 金币
- ✅ 不影响已存在的打卡记录

## 测试建议

1. **创建景点测试**
   - 不填写金币数（应使用默认值 10）
   - 填写有效值（如 20、50、100）
   - 填写边界值（1、1000）
   - 填写无效值（如负数、大于 1000）

2. **打卡测试**
   - 创建不同奖励金币的景点
   - 打卡后检查是否获得对应金币
   - 查看金币交易记录

3. **UI 测试**
   - 移动端表单布局是否正常
   - 输入框提示文字是否清晰
   - 表单验证是否生效
